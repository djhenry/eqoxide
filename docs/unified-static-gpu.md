# Unified static visual GPU inspection

This path renders the common static visual artifact through `eqoxide_renderer::static_visual`, independently of the legacy zone loader and the game loop. The bounded CPU decoder supplies server-axis meshes, material semantics, exact PNG payloads and instance matrices. `PreparedStaticVisual::decode` creates private preparation data; `GpuStaticVisual::upload` builds a complete resource set. The caller owns its render pass, color/depth targets and submission. Drawing fails until camera preparation succeeds; failed camera preparation invalidates prior prepared state rather than permitting a stale camera draw.

This is neutral, unlit material inspection. It applies no lighting, fog, shadow or physical material model. Production zone resources, shaders, online reader advertisements, collision/navigation and lifecycle are unchanged. GPU inspection is separate from production reader support and gameplay readiness; interactive preview is a subsequent consumer.

The shader computes texture RGBA times material RGBA times interpolated vertex RGBA. Texture RGB is interpreted as sRGB and converted to linear; material factors, vertex colors and alpha remain linear. Opaque ignores alpha for coverage and writes alpha one. Mask discards only below the actual material cutoff using the full alpha product; surviving fragments write alpha one. Blend uses straight alpha, depth tests against solid surfaces and does not write depth. Single-sided materials cull back faces; double-sided materials show both faces. Geometry and instance matrices use decoded server axes directly, without another source-axis conversion.

Meshes share position/primary-UV buffers and instance records. Normals are validated by the CPU decoder but are not uploaded or used by this unlit pass. A later lighting profile must define their transformation and face orientation. Colored primitives have separate full RGBA streams; uncolored primitives use white. Images are uploaded once even when multiple texture indices alias them. Names and generator metadata select no behavior; a visual mesh named `__collision__` remains visual.

PNG input is converted to float32 without reducing 16-bit samples to eight bits. Texture RGB receives the sRGB transfer conversion; alpha does not. GPU images use `Rgba32Float`, a nonfilterable binding and explicit repeat/bilinear sampling through `textureLoad`, so optional float-filtering device features are unnecessary. UVs wrap before integer addressing, including negative and large finite coordinates. Inspection uses the base image level without mipmaps or anisotropic filtering. Final PNG output uses an eight-bit sRGB target; precision-sensitive alpha decisions occur before that output encoding.

Float texture payloads cost four times as much as RGBA8 and twice as much as RGBA16. These are GPU payload limits, not bounds on peak CPU preparation memory. PNG decoding and conversion can transiently retain source pixels and a float image; preparation transforms that owned float buffer in place instead of allocating another full float copy. Unreferenced declared images remain validated, prepared, counted and uploaded under the same limits. Default upload limits are 512 MiB across buffer/texture payloads, 64 MiB per float image and 1,000,000 draw commands. The checked primitive-instance blend-command product is bounded before command allocation or texture conversion. Geometry/color/index/instance buffers, material/camera uniforms and fallback resources contribute to accounting. Device buffer and texture limits are checked before allocation. These payload budgets do not bound total process memory or driver overhead; callers can provide explicit overrides. Decoder limits apply separately before GPU preparation.

Opaque and masked surfaces retain full instancing. Camera matrices follow the existing right-handed convention: camera-forward is negative view-space Z, with conventional WebGPU depth increasing from near zero to far one. Camera preparation checks finiteness and multiplication overflow; callers are responsible for supplying this convention. Blend draws use stable camera-depth order per primitive-instance, with centers derived from the primitive's referenced vertices. This common sorting policy does not solve intersecting transparent surfaces, transparent cycles or ordering within a primitive. Those limitations must be addressed separately before declaring broader production fidelity.

Display inspection requires `Rgba8UnormSrgb` output; linear UNORM targets are rejected. Shader math and blending remain linear, and the attachment encodes RGB for display. `Rgba32Float` unfiltered texture binding is part of the baseline device format contract; no optional float-filtering feature is requested. Hardware or validation failures still return an error, and finite adapter testing does not certify every GPU.

The standalone example requires a working GPU adapter and returns a nonzero error if the artifact, device, upload or readback fails:

```sh
cargo run -p eqoxide-renderer --example static_visual_render -- INPUT.glb OUTPUT.png
```

It bounds the input read, frames the validated server-world bounds, renders a 512-by-512 image against an opaque dark background, and writes an actual PNG from GPU readback. The opaque background avoids interpreting a premultiplied transparent framebuffer as a straight-alpha PNG. It prints inspection statistics and the adapter/output details; it does not start a game account, network task or asset-server session.

For a native-free input, use `crates/eqoxide-assets/tests/fixtures/static-visual-v1.glb`. The fixture has one mesh shared by two transformed instances; its server bounds are `[-3,-7,2]` to `[16.44179,13,6.5]`. Actual GPU acceptance must separately verify material factors, full vertex RGBA, alpha modes/cutoff, sidedness, coordinate placement and precision. Shader parsing alone does not prove rendering correctness.
