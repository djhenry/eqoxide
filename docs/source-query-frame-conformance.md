# Preserved source query-frame conformance

Run the new paired CPU check with explicit checkouts:

```sh
python3 scripts/check-source-query-frame-declaration.py CLIENT_CHECKOUT PRODUCER_CHECKOUT
```

Both checkouts need their locked Cargo dependencies available offline. The checker uses only Python's standard library and invokes actual producer examples and client collision/package probes with `cargo run --locked --offline`. It owns and cleans its temporary output directory. It reports both Git commits and each checkout's dirty scope; a dirty run is evidence about those working trees, not clean-commit acceptance. A change in commit or dirty scope during the run refuses acceptance. Keep source trees stable during validation.

The optional `SOURCE_QUERY_FRAME_PRODUCER_TARGET_DIR` and `SOURCE_QUERY_FRAME_CLIENT_TARGET_DIR` environment variables select separate warm build targets. Otherwise Cargo uses its usual configuration, including `CARGO_TARGET_DIR`. Apply the project's existing serial build/resource guard. A cold root-package probe build can exceed a short whole-check wall budget: prebuild the four producer examples, the `eqoxide-assets` collision probe, and the `eqoxide` package probe in separate bounded commands before running the checker against those warm targets. Do not increase guard limits implicitly. The warm check makes 44 sequential Cargo invocations; compilation diagnostics remain on stderr and its status summary stays compact.

The assertion uses capability `eqoxide-source-query-frames-preserved-v1`, API `QueryUnitFrames::DeclaredSourceQueryFramesPreserved`, report identifier `declared-source-query-frames-preserved`, and authored-fixture flag `--declare-preserved-source-query-frames`. This is an eqoxide bake-contract assertion preserving the supplied source collision query frames: decoded terrain world units, decoded model-local units with scale retained in instance matrices, quantization decoded first, and the existing exact axis conversion permitted. Unknown source frames remain unspecified. It establishes no universal EQ/RoF2 units, game identity, importer provenance verification, implemented query operation or native query agreement.

The checker generates all four authored families in default and declared modes. Static collision and EQG each supply nonempty and known-empty collision roles. The descriptor fixture supplies its actual visual/collision package. WLD supplies mixed, known-empty and deliberately policy-inconsistent packages. Every collision GLB goes through the actual bounded role decoder, including the valid collision component inside the WLD disagreement package. Available packages go through the actual assembled-file package decoder with the generated manifest revision and explicit manifest/descriptor file pairs. Both WLD disagreement packages must fail specifically on collision policy mismatch. Producer summary claims about component decoding are not evidence.

The role checks require the exact capability set, expected frame identifier and `segment_queries_implemented=false`. Package checks require matching collision frame/counts/bounds/policy, verified assembled file content, `runtime_activation=false`, and `segment_queries=false`. Individual CAS chunk verification remains false. Component bytes are verified by the package decoder; the checker adds no new hash dependency.

Across modes from the same producer, the checker compares the entire decoded GLB JSON and binary chunk after removing only header `bakeRevision` and `requirements`. This includes complete local geometry pools, nodes, poses, accessors and other metadata, rather than only samples or world bounds. Bake revisions must differ because declaration mode contributes to identity. The descriptor fixture's visual GLB is checked too.

The retired explicit capability `static-collision-query-unit-frames-v1` is deliberately refused. The checker changes only that capability value in otherwise valid declared available/known-empty roles, rebuilds legal bounded GLB JSON framing, and requires actual role-decoder refusal for unsupported collision requirements. It also requires the retired `--canonical-query-units` flag to fail before creating output for all four generators. Fully rehashed old-tag package negatives belong to the client test suite; a package with stale hashes would not prove declaration semantics. Default unspecified assets remain supported.

All four example identities include their source bytes, and their declared mode contributes an additional identity input. Renaming therefore intentionally changes freshly generated revisions and bytes even in default mode, including the descriptor fixture's visual GLB. The producer's EQG derived-revision scheme and WLD authored exponent-2 geometry are distinct from unchanged shared helper defaults. This checker compares new producer modes with each other and makes no historical byte-compatibility promise. Existing committed fixture binaries, historical producer pins and their separate conformance scripts remain independent and unchanged.

The paired workflow should pin the producer implementation commit, followed by a reciprocal producer CI-only update pinning the accepted client commit. This ordering avoids cyclic source pins; the checker itself hardcodes neither checkout revision and commits no new GLBs. Its ceiling is CPU producer-to-reader artifact conformance. It supplies no native/game execution, engine tolerance/policy proof, complete-world claim or gameplay activation.
